# Overhead — project conventions for Claude Code

Read `OVERHEAD-PLAN.md` first. It is the spec. The interactive reference (diagrams, layer toggles, request trace, VPC collapse) is the artifact linked at the top of it — fetch it with WebFetch when you need the visual.

## Non-negotiables

- **Prove the pipe first.** No feature work until a deployed page on Vercel registers one tool that executes from the ChatGPT desktop browser's Site tools. Every silent failure mode (iframe, SSR-time registration, wrong model, deprecated `navigator.modelContext`) looks identical: no tools appear. Verify before building.
- **`document.modelContext`**, with `navigator.modelContext` as fallback. Never `provideContext`, never `unregisterTool` — abort with `AbortSignal`.
- Register tools in one `'use client'` provider mounted at the root, after hydration, in the top-level document. Imperative API only.
- `src/webmcp/register.ts` must contain a raw `document.modelContext.registerTool({ name, description, inputSchema, execute })` call in that literal shape — the brief says repos should have it. Wrap it in hooks elsewhere; don't hide it.
- Every mutation updates the store **before** the tool returns, so the agent's next read sees reality.
- Read tools carry `annotations.readOnlyHint: true`. Anything returning parsed bill content carries `untrustedContentHint: true`.
- Tool outputs ≤ ~1.5K characters. Chunk anything bigger via `get_export_chunk`.
- Tool names ≤ 30 chars, descriptions ≤ 500, parameter descriptions ≤ 150. Validate strictly in code, loosely in schema; return structured errors the agent can recover from.
- No backend, no auth, no API routes. Static export. Everything runs in the tab.
- Pricing numbers come from `data/pricing.<region>.json`, generated by `scripts/fetch-pricing.ts` from the AWS Price List Bulk API. **Never hardcode a price.** Every SKU line keeps its `sourceUrl`.
- Every finding returns a `docUrl`. No finding without a citation.
- MIT licence at repo root. Official AWS icons live in `public/icons/aws/` with `NOTICE.md` carving them out of the MIT licence.

## The spine

`src/engine/services/<service>.ts` — one `defineService()` per AWS service. The inspector form, `set_property`'s input schema, `list_services`, the card's three lines, the pricing function, and the CDK props are all **derived** from it. If you find yourself hand-writing any of those per service, stop and derive instead.

## Diagram language (summary — full rules in the plan §5)

- Nodes are the AWS standard: 56 px official icon + name. Zoom ≥ 125% (or Cards / Cost on) → the icon moves inside a 200×76 card with term, name, settings, badge, cost. Nothing hangs loose outside the icon.
- Edges: `sync` solid + arrowhead · `async` dashed `7 5` + arrowhead · `data` dotted `2 5`, no head. Nothing else is an edge; permissions/logging/encryption are node properties.
- All edges are cubic beziers. Same-column: bracket out one side. Long hops: low arch. No elbows.
- Lanes left→right: Ingress → Handlers → Messaging → Workers → Data.
- Layers: request · events · data · security · cost. Default on: the first three.
- Groups use official frames/colours and collapse to one card with a subtotal.
- Vector always: SVG canvas, `<use>` of the official icon symbols, zoom scales coordinates. Pan/zoom/drag/containers come from React Flow — never reimplement them. Zoom UI: −/+, slider, Fit, ⌘/Ctrl+scroll.
- `reference/diagram-module.js` implements the geometry in vanilla SVG (cards, bezier routing, layers, hover, trace, drag, groups, collapse). Port to React Flow custom nodes/edges; do not ship it.

## Look and feel

Direction is **Instrument**: dark, dense, pro-tool. Canvas bleeds edge to edge, chrome floats over it, left icon
rail with keyboard hints, floating layer switch and zoom pill, title block in the canvas corner, agent strip at
the bottom. Tokens and layout in the plan §11. `reference/overhead-mock.html` is the target — match it.

- Never a row of labelled pill buttons. Tools are icons on a rail with a keyboard hint and a tooltip.
- Progressive disclosure: the inspector is empty until something is selected; cost only appears in card mode.
- The grid is toggleable (rail button, ⇧G) and fades rather than unmounting.
- Uppercase is for 9.5 px labels at .14em tracking only — never for buttons or body.

## Engine is pure TS

`src/engine/**` imports nothing from React or the DOM. Cost and findings are derived selectors, never stored. Vitest covers: one test per rule, one per exporter, a golden monthly cost for each of the three samples. `cdk synth` runs on all three sample exports in CI.

## Testing tools

Test each tool from the ChatGPT desktop browser as you add it, not at the end. Second path: Chrome with `chrome://flags/#enable-webmcp-testing` + the Model Context Tool Inspector extension.

## Commits

Small, frequent, inside the submission window. Conventional messages (`feat(engine): …`, `feat(webmcp): …`, `feat(canvas): …`).
